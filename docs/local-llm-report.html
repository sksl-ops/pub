SUMMARY

要約

「秘匿している」は半分本当で、半分は観測の錯覚。公開情報を拾うと、用途は5層に分かれる。語られないのは、①性的な用途、②守秘義務のある実務、③個人の機微データ、④地味すぎる雑用、⑤趣味としての調整そのもの。

そしてローカルが選ばれる理由は、強い順にこうなる。

  1. クラウドに渡せない（機密・規約違反・拒否・ログ）— 代替不能
  2. 提供元に止められたくない（規約変更・BAN・レート制限）— 保険としての価値
  3. 大量に回す／無制限に試す（コスト）— 条件付きでしか成立しない
  4. オフライン・低レイテンシ・自由な改造 — 用途依存
  5. 楽しい・差別化・所有感 — 費用対効果の計算に乗らない

LAYER 01

性的な用途 — 最も言えないが、最も具体的に動いている

ここだけは、匿名性を保てる場所でなら驚くほど具体的に語られている。

01-A

LLMでエロゲを作っている人

開発進捗を公開している珍しい例

@ARYKEI（2026-09-14、208 likes・約3万表示）は、「常識改変」をシステムプロンプトに埋め込む手法を検証している。学校に「性欲処理係」があるという前提を注入すると、拒否されずに関係が進み、告白すると「係としてやってるだけ」と振られ、直後にまた予約が入る、という挙動になる。ローカルモデルだから拒否層に止められない、という前提で設計されている。

01-B

ローカルAIがGMをやるR18 TRPG

「なぜローカルか」が明記されている例

Ci-enの個人開発記事は、R18ゲーム「港湾都市の背徳譚」でローカルAI＋自作エンジンがGMを務めると明記し、オンラインLLMでNSFWを誘導すると各サービスの規約違反になるためローカルを使う、と理由まで書いている。

01-C

官能小説・ダークな創作

無検閲モデルの実務的な使い方

実務ガイドでは、拒否層を外した Hermes 3 / Dolphin 3.0 を Ollama に置き、SillyTavern や Agnai から繋ぐ構成が定番とされる。日本語については「無検閲ファインチューンは英語データ中心なので日本語が弱い」「まず標準モデルで足りるかを試せ」という注意まで付いている。コミュニティ製の日本語向け無検閲モデル（例: G4-MeroMero-31B）も存在する。

01-D

NSFW画像

厳密にはテキストLLMではない

@gin1910410（216 likes）は「ローカルLLMなぜやってますか？→無限画像生成と垢BAN気にせずできるNSFW」と断言する。ただしこれは拡散モデル（Stable Diffusion / ComfyUI）で、テキストLLMではない。日本語の「ローカルLLM」は画像生成まで含む括りで使われるため、質問と答えが噛み合わない現象が起きる。

観測

実名では書けないので、書くときは必ずネタ化する。面接の想定問答で「はい、いつも（えっちな画像を生成させるのに）使用しております」という投稿が2,832 likesを集めているのが、その証拠（@mgrwsli）。

LAYER 02

守秘義務のある実務 — 書くと顧客の話になる

士業向けの実務記事が具体的。TodoONada（2026-07）によれば、弁護士・税理士・社労士・行政書士の守秘義務は法律上の義務で、違反には拘禁刑や100万円以下の罰金がある。そのうえで、ローカルで実際に回しているのは次の作業だ。

士業の事務所でローカルに寄せている業務（出典: TodoONada）
業務内容
書面作成契約書・申請書・意見書の下書き
過去案件検索就業規則・ひな形・過去の意見書をRAG化して横断検索
要約議事録・打合せメモの要約
照会事務所内の規程・マニュアル照会

費用感はひとり事務所で Mac Studio 1台＋日本語モデル＋RAG の構成でハード40〜60万円＋構築費。ただしこの記事は「大半の業務は学習に使われない契約のクラウドAIで足りる」「ローカルが要るのは NDA・刑事/M&A/知財係争/破産のような機微な事件類型・事務所ポリシーでクラウド利用自体が縛られる場合」と釘を刺している。つまり「士業＝ローカル」ではなく、ローカルにしか出せない書類がある事務所だけがローカルに寄っている。

製造業も同じ構造だ。クラスメソッドの整理では、設計データ・品質検査記録・製造ノウハウは取引先との契約で外に出せず、工場のネットワークはインターネットから切られている。そこで動くのは品質報告書のドラフト、現場記録の要約・タグ付け、問い合わせの一次対応。要約しても外に出せない文書の処理だ。

この層が「言っても伝わらない」のは、具体例を書いた瞬間に「どの顧客の、どの案件か」が漏れるから。公開されるのは「便利でした」か、抽象化された業務名だけになる。

これらに共通するのは、内容を一行でも公開したら終わりだということ。使っている事実だけを言うと引かれ、内容を言うと社会的に終わる。だから「楽しい」しか書けない。

ANALYSIS

なぜ「秘匿」に見えるのか

原因1

語れる用途しか語られない

性能・ベンチマーク・機材・「楽しい」は語りやすい。顧客名・体調・性癖は語れない。結果としてタイムラインには前者だけが残り、後者が見えなくなる。これは隠蔽というより観測の非対称性だ。

原因2

「ローカルLLM」が指す範囲が人によって違う

テキストLLMを指す人と、Stable Diffusion を含む人と、エージェント全体を指す人が混在している。だから「何してるの？」への答えが噛み合わない。

原因3

語る動機が弱い

用途が地味で、説明しても伝わらず、自慢にもならない。ローカルLLMの調整自体が目的化している人にとっては、そもそも「用途」という問いが成立しない。

WHY LOCAL

クラウドでなくローカルにする理由

理由は「性能」でも「コスト」でもなく、ほぼ「統制（コントロール）」と「境界（外に出せるか）」に集約される。

理由 01

外に出せない・出したくない

最も強く、恒久的な理由

技術的な優劣ではなく、送信先が存在しないことが理由になる。

  • 守秘義務：士業は罰則付きの義務を負い、NDAや事務所ポリシーでクラウド利用自体が縛られる場合にローカルへ。
  • 規約で禁止される用途：R18ゲーム開発者は規約違反を明記してローカルを選ぶ。
  • 「拒否」で作業が止まる：@celsius220は「サイバーセキュリティを理由に処理を拒否され、KimiやGLMを試したら完了できた」「拒否によって損なわれるのは時間でも金でもなくツールへの信頼だ」と書く。回復しない種類の損害。
  • ログと学習：API側の監査ログ保持（最低30日、削除不可）を嫌って自前運用にする例（Ask HN）。

「クラウドは処理のために送る、ローカルは送る先そのものが無い」（@WEBMARKS2）。この言い方が一番本質を突いている。

理由 02

提供元の都合で使えなくならない

性能比較では測れない価値

直近の実例は @tosu2。Claude Code が「既存ゲームの再現」を禁止するルールを追加した（2026-11-02）ことへの反応で、「提供元の方針変更でAIの使える範囲が変わる」「性能ではクラウドに敵わなくても、使い慣れたモデルをそのまま手元に残せる。性能比較だけでは測れない価値がある」と書く。

同種の理由として、レート制限・クォータ・時間帯を気にしなくてよくなる点を挙げる開発者もいる（HN事例のheipei氏）。「プロプライエタリなツールをプログラミングに使うことに抵抗がある」ので、そもそもフロンティアモデルを本格使用していないというlambda氏の例も同じ層だ。モデルの重みを手元に置けば、サービス終了・値上げ・規約変更でワークフローが壊れない。

理由 03

環境・速度・自由度

  • オフライン／閉域：ネットにつながっていなくても動く（impress）。工場の閉域網、現場、移動中。
  • 待ち時間の安定：TTFTはローカル50〜200ms、クラウド200〜800ms（SitePoint）。混雑で跳ねないことは補完系UIで効く。
  • 大量のバッチを順番待ちで流せる：@kirin_sg87は「コストを気にせず回し続けられるからタスクを順番待ちさせとけばいい」と書く。
  • 自由にいじれる：ファインチューニング、量子化、システムプロンプト、コンテキスト長まで自分で決められる。無検閲モデルの選択もこれの一部。
理由 04

楽しい・差別化・所有感

gihyoの著者は「ローカルLLMを使ってみること自体の価値」として差別化を挙げる。クラウドは資本力で均質化するが、ローカルの体験は均質になりにくい、という主張だ。「自由とロマンと自由、変わらない安心感、冬は暖かい」（@gin1910410）も同じ層。費用対効果の計算に乗らないこと自体が理由になる。

COST

コストの現実 — 「無料」は条件付き

「ローカルは無料」は最もよく言われる理由だが、数字で見ると個人の少量利用ではほぼ成立しない。

肯定側の一次証言としては、@hokazuya（415 likes・約8.3万表示）がChatGPT Pro 5x以外のAIサブスクをほぼ全部解約し、「自作ローカルLLMとOpenRouter経由のAPIで適宜ルーティングしていれば、月額数十ドルでタスクは滞りなく回る」と報告している。HNでも月100ドルのClaudeサブスクをやめた例がある。

12か月TCOの比較（出典: SitePoint、2025年6月時点の価格・TDPに基づくモデル計算）
利用量クラウドAPI（OpenAI）ローカル（コンシューマ機）
50万トークン/日$1,260$6,457
500万トークン/日$12,600$18,387
5,000万トークン/日$126,000$308,347（企業向け構成）
  • 実効単価はクラウド $6.90/100万トークンに対し、ローカルは$35.37。
  • 損益分岐はコンシューマ構成で日量200〜300万トークン、オープンウェイトのホストAPI相手だと日量1,500〜2,000万トークンまで上がる。
  • 電気代はRTX 5090を8時間/日で年$190、24時間稼働で年$570。運用保守は軽量利用でも月2〜4時間（時給$75換算で年$1,800）。

つまり「コスト削減」は大量に回す人か、機材を既に持っている人、あるいは無制限に試したい人の理由になる。gihyoの著者も「コストが3倍になってもクラウドLLMのほうが安い」と明言している。さらに2026年夏〜秋にはOpenAIとAnthropicが相次いで料金を値下げしたとされ（GIGAZINE 2026-10-29付、@celsius220が引用）、コスト面の差はむしろ縮んでいる。

CONCLUSION

まとめ

  1. クラウドに渡せない（機密・規約・拒否・ログ）— 代替不能
  2. 提供元に止められたくない（規約変更・BAN・制限）— 保険としての価値
  3. 大量に回す／無制限に試す（コスト）— 条件付き
  4. オフライン・低レイテンシ・自由な改造 — 用途依存
  5. 楽しい・差別化・所有感 — 計算外

逆に言えば、性能だけを求めるならクラウドだ。impressの記事も「仕事に確実に役立つという意味ではまだクラウドに分がある」と書いている。実際、@kirin_sg87 や @hokazuya の運用は「ローカル一本」ではなく、ローカル＋安価なAPIのルーティングである。

ローカルはクラウドの代替ではなく、クラウドに通せないものを置いておく場所として使われている。魔術師なのではなく、答えられないだけだ。
